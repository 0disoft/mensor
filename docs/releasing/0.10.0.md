# Mensor 0.10.0

Status: Published to npm on 2026-09-10. This supersedes the unshipped 0.9.1
candidate and includes its runtime, compiler and toolchain changes.

## New Behavior

`mensor index-hono-jsx-forms` produces an explicit source-bound FormIndex from
the bounded HonoX subset. Callers name TSX sources, a standalone JSX config,
a static Vite config and a transparent Hono renderer. None are executed.
See [the input contract](../architecture/hono-jsx-form-index-v1.md).

The compiler adds the `@0disoft/mensor-compiler/hono-jsx` subpath containing
`extractHonoJsxFormDocument`. This is a pure syntax primitive; activation is
the caller's responsibility. Package-root exports and the FormIndex revision
are unchanged.

## Compatibility

Upgrade `@0disoft/mensor-contract`, `@0disoft/mensor-compiler`,
`@0disoft/mensor-cli` and `@0disoft/mensor-reference-runtime` together to
0.10.0. Existing check, compile and index commands retain their behavior.
There is no database or serialized schema migration.

Selected JSX activation files must be inside the consuming project's
discovered source tree or explicitly named in its new optional
`formIndexEvidence` list. This allows root-level build settings without moving
the application or widening source discovery. The additive project-contract
field requires Mensor 0.10.0; older consumers reject it. Their digests are stored as empty activation documents
so existing freshness validation rejects stale settings. Runtime deployment,
outer middleware, custom transforms and dependency authenticity are not
attested. Nested renderers and custom Vite plugins are not supported.

All four packages are available as 0.10.0 on the npm `latest` tag.

The maintained guarded RSVP example supports bounded read-only context helpers
and `Array.from` lists with const snapshots and exact string guards. Ordinary
opaque map receivers, unchecked values, nested renderers and custom transforms
remain unsupported. Static HonoX routing is not configured; the example's real
HTTP tests provide separate runtime evidence.

## Release Conditions

Before publication, require the aggregate local check, local package-consumer
smoke and the guarded RSVP workflow. Its dedicated gate covers real HonoX
GET/POST and bounded loopback-server lifecycle. Browser verification additionally
checks native form submission, redirect and escaped list content.
Create the four 0.10.0 tarballs with `mensor_release_pack` and review
`dist/release/manifest.json`. Local artifacts do not imply npm publication.
The final release still requires a clean reviewed commit and successful remote
CI for that exact commit; preserved unrelated working changes are not release
evidence and must not be silently included.

Local preflight on 2026-09-10 passed `mensor_check` (including package smoke,
contract/schema checks, the 1,000-file performance smoke and adoption pilot),
the seven-test guarded RSVP gate and an in-app browser form submission. The
bounded browser server exited and was reaped. Four local 0.10.0 tarballs were
generated and their SHA-256 values matched the release manifest.
The original lockfile delta was subsequently reproduced byte-for-byte by a
clean frozen install and committed as pnpm executable metadata. Clean candidate
verification and the native pnpm/Windows CI launch fixes followed.

## Installed Consumer Gate

Package smoke installs the local tarballs, imports the public JSX subpath,
and checks the maintained guarded RSVP example without its checkout runner.
Its source mutation must fail freshness before regeneration and report a missing
email field afterward. The same installed CLI also
generates an index, runs `check`, and verifies configuration freshness and
form-field drift. It also verifies that the unchanged RSVP trial passes read-only
helper activation while retaining incomplete dynamic-list evidence and no forms.
This does not turn the trial into a supported application or prove its runtime
semantics; custom route preludes and opaque dynamic siblings remain deferred.
