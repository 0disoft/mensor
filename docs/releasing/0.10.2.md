# Mensor 0.10.2

- Status: Published and registry consumer verified 2026-09-12

## Packages

All workspace versions remain aligned at 0.10.2:

- `@0disoft/mensor-contract`
- `@0disoft/mensor-compiler`
- `@0disoft/mensor-cli`
- `@0disoft/mensor-reference-runtime`

## Compatibility

Human `check` and `compile` failures for missing project contracts now name
the selected root-relative config path and suggest checking the root or
`--config`, or creating the project and referenced feature contracts.
Missing parent directories are covered; missing project roots, unrelated
feature files, permission errors and wrong file types do not get this hint.

No files are generated or reread. Existing JSON envelopes, public APIs,
`path.missing`, filesystem failure classification and exit status 3 remain
unchanged. Producer metadata reflects the package version. Valid projects
require no migration.

## Publication

All four packages are published on `latest` by the
[OIDC release run](https://github.com/0disoft/mensor/actions/runs/34681746618)
from commit `21be2de0fda6db3f4c9ae102328a8ccffd63ad81`. Both required push
workflows passed for this exact commit before dispatch.

The installed-tarball gate covered missing default and custom config paths,
missing parents, human check/compile output, unchanged JSON v1/v2 failures,
exit status 3 and absence of generated files.

The first registry install attempt could not yet resolve the compiler version.
After registry metadata updated, `mensor_registry_smoke` installed all four
exact 0.10.2 versions in an isolated consumer and passed public imports,
compilation, route/form indexes, JSX freshness and field-drift controls, SARIF
and valid/invalid project checks. The invalid control intentionally emitted
`form.field_missing`. Publication was not rerun.

The `v0.10.2` tag identifies the package publication commit, not the later
documentation update. Future releases follow the [release runbook](runbook.md).
