# Mensor 0.9.1

- Status: Release candidate; not published to npm.

## Package Set

The fixed-version workspace prepares these public packages at 0.9.1:

- `@0disoft/mensor-contract`
- `@0disoft/mensor-compiler`
- `@0disoft/mensor-cli`
- `@0disoft/mensor-reference-runtime`

## Changes

The reference runtime rejects redirect locations containing raw backslashes or
control characters and checks the resolved origin. Ordinary root-relative
paths, query strings, and fragments remain supported. Hosts returning ambiguous
redirect locations must encode or replace those locations before upgrading.

Compiler reads allocate the observed file size plus one byte, instead of the
configured maximum. The extra byte and post-read checks continue to reject
growth, truncation, size-limit violations, and file-identity changes.

The aggregate `check` gate reuses the clean build performed by `test`, which
also type-checks all workspace packages. Contract, migration, smoke, package,
release, performance, adoption, and documentation checks remain in the gate.
Standalone validation commands retain their existing build prerequisites.

The workspace fast-uri override is updated to ^3.1.7. Workspace overrides do not
force an existing downstream application's lockfile to update.

Development dependencies use Hono ^4.13.7 and pnpm 11.26.0. The contributor
toolchain requires Node 22.13 or newer; published packages retain Node >=22.
Checkout and setup-node use reviewed v7 revisions, with the existing workflow
triggers, permissions, and cache inputs retained. See the
[dependency checklist](runbook.md#dependency-update-checklist) for migration boundaries.

Module-boundary traversal prefetches source reads in batches of at most eight.
Parsing and diagnostic order remain serial, with the existing file-identity and
mutation checks intact. See the [local experiment](../performance/representative.md)
for timing, memory, and measurement limitations.

## Compatibility

Public API signatures, schema revisions, diagnostic identifiers, and CLI output
formats are unchanged. No data migration is required. Publication and registry
verification remain separate steps in the [release runbook](runbook.md).
