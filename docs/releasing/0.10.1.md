# Mensor 0.10.1

- Status: Published 2026-09-11; registry consumer verified 2026-09-12

## Packages

The workspace versions remain aligned at 0.10.1:

- `@0disoft/mensor-contract`
- `@0disoft/mensor-compiler`
- `@0disoft/mensor-cli`
- `@0disoft/mensor-reference-runtime`

## Compatibility

Human CLI configuration failures now include a bounded hint when an enum
decoder is otherwise valid but contains unsupported properties. The hint names
the decoder path and explains that only `kind` and `values` are accepted;
`trim` and `empty` are text-decoder options. Other malformed decoder cases
retain the existing failure line without this hint.

No contract schema, public API, JSON envelope, diagnostic code or exit code
changes are required. JSON producer metadata reports the new package version.
Existing automation should continue using `--json` rather than parsing human
stderr. No migration is needed for valid contracts.

## Release Boundary

All four packages were published on `latest` by the
[OIDC release run](https://github.com/0disoft/mensor/actions/runs/34594341773)
from commit `47a5b4e4e3accc7083d955527ba7670933f0a4f6`. The exact commit passed
both required push workflows before dispatch.

Initial post-publication installation attempts encountered missing registry
metadata and then a compiler tarball HTTP 404. No publication was rerun.
On 2026-09-12, `mensor_registry_smoke` installed all four exact 0.10.1 versions
in an isolated consumer and passed contract imports, compilation, route and
form indexes, JSX freshness and drift checks, SARIF, and the valid/invalid
project controls. The invalid control intentionally reports
`form.field_missing`; it is not a failed smoke run.

Historical onboarding evidence remains tied to the exact 0.10.0 packages it
tested; it is not 0.10.1 package-install evidence. Future releases follow the
[release runbook](runbook.md).
